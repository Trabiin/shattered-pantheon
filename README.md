# Shattered Pantheon

A mobile auto-battle gacha game, built in Unity. Design docs live in the project's shared folder (`plan/`).

## What's here

| Folder | What it is |
|---|---|
| `Unity/` | The game. Open this folder in Unity Hub. |
| `Unity/Assets/BattleCore/` | The battle rules, the order campaign battles open in, how heroes grow and what it costs (`Growth.cs`), what the campaign expects at each battle and the battle XP of a first win (`CampaignCurve.cs`), and how a summon works (`Summon.cs`: cost, rates and guarantees), all from `progression.json`: plain C# with no Unity code, shared by the game and the simulators. |
| `Unity/Assets/Resources/BattleData/` | Heroes, enemies, the campaign, the simulator's test stages and rules as JSON. The one copy both the game and the simulators read. Generated by `tools/BattleData/` and `tools/ProgressionSim`. |
| `Unity/Assets/Game/` | The game screens, built in code with placeholder art: campaign, team and formation, battle, results. `Scripts/Save/` keeps the player's progress, heroes and items on the device; every change to heroes and items goes through `Wallet.cs`. |
| `tools/BattleData/` | The script that writes the battle data, and a guide to its format. |
| `tools/FightViewer/` | A browser page that replays real engine fights turn by turn (`build.py` explains how to rebuild it). |
| `tools/ProgressionSim/` | The progression and economy simulator: simulated players play a year of the campaign day by day, every campaign battle a real fight. Reads `progression.json` and `campaign.json`. |
| `tools/BattleSim/` | The balance simulator, compiled from the same `BattleCore` files. It fights the 6 test stages in `stages.json`. |
| `tools/SaveTests/` | Tests for the game's save file (`Unity/Assets/Game/Scripts/Save/`). |
| `tools/CampaignTests/` | Tests for the order campaign battles open in (`Unity/Assets/BattleCore/CampaignOrder.cs`). |
| `tools/GrowthTests/` | Tests for the hero growth and cost rules (`Unity/Assets/BattleCore/Growth.cs`). |
| `tools/SummonTests/` | Tests for the summon rules (`Unity/Assets/BattleCore/Summon.cs`). |
| `reports/latest.md` | The latest balance report. |
| `reports/progression.md` | The latest progression report. |

## Open the game

1. Install **Unity Hub**, then **Unity 6.3 LTS** with *Android Build Support* (and *iOS Build Support* on a Mac). The project names its exact editor in `Unity/ProjectSettings/ProjectVersion.txt` (6000.3.26f1); if you have a different 6.3 version, Unity Hub offers to install that one or open with yours.
2. Clone the repository (for example with GitHub Desktop, or `git clone https://github.com/Trabiin/shattered-pantheon.git`).
3. In Unity Hub: **Add > Add project from disk**, pick the `Unity` folder inside the clone, and open it. The first open takes a few minutes while Unity imports everything into `Unity/Library/`.
4. In the Project window, open `Assets/Scenes/Main.unity` and press **Play**. If the scene is missing, use the menu **Shattered Pantheon > Rebuild Main Scene**.
5. In the Game view, pick a portrait phone resolution (for example 1080x1920) to see it as on a phone.

If Unity won't open the project because "another Unity instance is running", a Unity process from an earlier session is still running: end it in Task Manager (or Activity Monitor on a Mac) and open the project again.

The repository holds everything a fresh clone needs: `Unity/ProjectSettings/`, `Unity/Packages/` and a `.meta` file beside every file and folder in `Unity/Assets/` (Unity keeps each asset's id there, and the scene finds its scripts by those ids). What Unity makes for each computer (`Library/`, `Temp/`, `Logs/`, `UserSettings/`, `obj/`) stays out of git (`.gitignore`). When you add a file under `Unity/Assets/`, commit the `.meta` file Unity makes beside it; the Unity compile check fails without it.

The game opens on the campaign: realm 1 (Hearth) on Normal, its 10 stages with 4 battles each (battle 4 is the stage boss; stage 10's is the realm boss). Battles open in order: a new game opens only the first battle, each win opens the next, and beating a stage boss opens the next stage (locked battles are greyed out and say **Locked**). Cleared battles can always be replayed. Tap an open battle, set your team and formation (tap a slot, then a hero; the formation button switches between 2 in front and 3 in front), and press **Fight!**. The team screen lists your heroes with their level and star rank, and starts with your strongest five (with a Tank and a Support). The fight plays itself (tap the speed button for 1x/2x/3x, **Retreat** to go back), then the results show what each hero did, and won battles show as **Cleared**.

Until summoning arrives, a new game owns all 20 test heroes, each at level 1 and the star rank their rarity starts at (Common 1★ up to Legendary 5★). Heroes fight at their own strength: rarity, level, star rank and skill level (doc 07). The first win on a battle shares its battle XP evenly among the heroes who fought (replays give none yet); whenever a hero's XP reaches the next level they level up, with no gold, up to their star rank's level cap. Items (gold, XP potions, skill tomes, Vessels, Rebirth Scrolls) are kept but can't be earned or spent in the game yet.

## Testing tools (Unity editor and development builds only)

These are for testing and are never in a release build (they switch on with Unity's `Debug.isDebugBuild`, which is true in the editor and in builds made with *Development Build* ticked):

- **Testing speeds:** the battle speed button goes on past 3x to **10x** and **20x**, so a whole realm can be played quickly.
- **Fight log:** every battle writes what happened to the Console (**Window > General > Console**). The first line names the battle, its seed and both teams; then one line per action, starting with the fight time at 1x and the action number, holding everything in it: turns, skills and ultimates, damage, healing, shields, effects (and resists), rituals starting and completing, interrupts, deaths, and the result. Units that share a name also say where they stand. To find one thing (an interrupt, a death), type a word from it ("interrupts", "falls", "ritual") in the Console's search box. The log only reads what the battle engine already reports, so a release build does no extra work.

## Your save

Progress is kept in one file on the device, `save.json`, written after every battle and whenever the app is paused or closed. It holds the stars earned on each battle (a win is 1 star until star challenges arrive), the furthest battle cleared on each difficulty, the team of hero cards last used on each battle, the hero cards you own (`heroes`: every copy of a hero is its own card, keyed by card id, with its `hero`, level, XP towards the next level, star rank and skill level; a hero's first card has the hero's own id, like `hilde`, and later copies add `#2`, `#3`) and your items (`inventory`: gold, XP potions counted in XP, skill tomes, Vessels by star rank as `vessel1` to `vessel5`, and Rebirth Scrolls). Which battles are open isn't saved: it's worked out from the cleared ones. A new game's heroes are written with the first save; a save from before heroes were kept gets them when it loads. It lives in Unity's [persistent data folder](https://docs.unity3d.com/ScriptReference/Application-persistentDataPath.html):

| Where the game runs | Folder |
|---|---|
| Unity editor or a build on Windows | `%USERPROFILE%\AppData\LocalLow\Shattered Pantheon\Shattered Pantheon\save.json` (Unity also keeps its own `Unity` folder there) |
| Unity editor or a build on a Mac | `~/Library/Application Support/Shattered Pantheon/Shattered Pantheon/save.json` |
| Android | the app's own storage, `Android/data/<package name>/files/save.json` |

**To start again:** tap **Reset progress** at the bottom of the campaign screen, then **Tap again to reset**. Or close the game and delete `save.json`. The button is for testing and goes before the closed test.

**A damaged save** (one that can't be read) never stops the game: it's renamed to `save.damaged-<date>-<time>.json` in the same folder for checking, and the game starts new. The file is JSON with a `version` number; later systems (currencies, the daily loop) add their own sections, and a change that older saves need (a new format, or a renamed hero in a saved team) bumps the version and adds an upgrade step in `SaveData.cs`, so older saves keep working.

## Run the simulator

Needs the [.NET 8 SDK](https://dotnet.microsoft.com/download). From the repository root:

```
dotnet run --project tools/BattleSim                                    # full report -> reports/latest.md
dotnet run --project tools/BattleSim -- --team hilde,solenne,thessaly,maren,pip --stage saint --runs 500
dotnet run --project tools/BattleSim -- --log hilde,solenne,thessaly,maren,pip --stage saint --seed 1
```

The progression simulator (about a minute):

```
dotnet run --project tools/ProgressionSim -c Release                          # report -> reports/progression.md
dotnet run --project tools/ProgressionSim -c Release -- --build-campaign      # rebuild and sim-check campaign.json
```

## Checks without Unity

Every pull request runs these on GitHub (`.github/workflows/`):
- **Fresh clone:** `Unity/ProjectSettings/ProjectVersion.txt` names a Unity 6.3 editor (without it Unity Hub can't add the project) and every file and folder in `Unity/Assets/` has its `.meta` file.
- **Unity compile:** the game and editor scripts are compiled against the real Unity 6.3 libraries, taken from an official Unity editor image (from Docker Hub, or Google's copy of it if Docker Hub fails) and kept in GitHub's cache until a newer image comes out. No Unity licence is needed.
- **Screen smoke test:** `dotnet run --project tools/ScreenSmokeTest` plays the screens on a stand-in for Unity, like a player would (a card hit twice in quick succession going back to its own colour, locked battles can't be started, the first fights as a release build with no testing speeds and no fight log, then all 40 realm 1 battles in order as a development build at 20x with the fight log checked against every event, played by a new game's strongest team at its real levels, each win opening the next and sharing battle XP, retrying lost ones, results bars inside their rows, then closing and reopening the game, resetting progress, and two copies of one hero placed and fighting side by side), and fails on errors, on fights that differ from the engine, on heroes fighting at the wrong strength or on battle XP that doesn't add up.
- **Save tests:** `dotnet run --project tools/SaveTests` saves and reloads progress, heroes and items, and checks a new game and its heroes, damaged saves (and that their warning reads as whole sentences), upgrading an older version (version 1 saves keep the renamed heroes Jink and Korvald in their teams), saves from before heroes were kept, resetting, the wallet (earning, spending, refusing to overspend), battle XP and level caps, each hero's fighting strength, and copies of one hero as separate cards that grow, save and fight side by side.
- **Campaign order tests:** `dotnet run --project tools/CampaignTests` checks the order battles open in across all 4 difficulties: a new game, each win, stage and realm bosses, the next difficulty, replays and a reloaded save.
- **Growth tests:** `dotnet run --project tools/GrowthTests` checks the growth rules on the real `progression.json` against values worked out by hand from doc 07: health and attack multipliers, level caps, XP per level, fodder to ascend, skill tomes and gear costs.
- **Summon tests:** `dotnet run --project tools/SummonTests -c Release` checks the summon rules on the real `progression.json` against doc 08: the cost and rates, paying with a ticket before Godshards, a million summons rolling the doc's rates and never missing a guarantee, counters that carry over between sessions, the first-ten Epic rule and the same seed giving the same summons.
- **Battle data:** the files `tools/BattleData/gen_data.py` writes match the ones in the repository, and its checks pass (kits fit their rarity, no names close to a god's).
- **Replays:** the same seed always gives the same fight, so replays and server checks work.
- **Simulators run:** the balance report and a short progression run complete without errors.
